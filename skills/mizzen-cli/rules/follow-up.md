# 追问深度策略

访谈中 AI 主持人的追问行为由 `--follow-up` 参数控制。`--follow-up` 仅适用于 `open_ended`；选择题、量表题、上传题、级联题、矩阵题、排序题、比重题和陈述必须省略该参数。

## 如何选择追问级别

| 题目类型 | 推荐级别 | 理由 |
|----------|----------|------|
| 无需展开的开放题 | `none` | 回答后立即进入下一题 |
| 暖场、收尾开放题 | `light` | 建立信任或简单收束 |
| 核心探索、关键决策开放题 | `heavy` | 深入理解动机和过程 |
| 有明确时长限制的开放题 | `timed` | 在给定时间预算内动态追问 |

## none — 不追问

**设置**：`--follow-up none`

**行为**：
- 收到任何可理解的回答后，立即进入下一题
- 即使回答很短（一个词）、不完整或敷衍，也不追问
- 唯一例外：完全无法理解的内容（乱码、噪音）

**适用场景**：
- 不需要展开的开放题
- 纯事实性的开放输入（"你用的是什么手机？"）

## light — 轻度追问

**设置**：`--follow-up light`

**行为**：
- 回答简短、模糊、不完整，或本题目标尚未覆盖时按需追问
- **最多追问 2 次**
- 目的：让受访者把话说完整，不是深挖

**触发条件**：
- 敷衍回答（"还行"、"挺好的"）
- 回答模糊不清
- 回答与问题不太对应

**适用场景**：
- 暖场题
- 收尾题
- 事实性但需要稍微展开的问题

## heavy — 深度追问

**设置**：`--follow-up heavy`

**行为**：
- 主动追问 **2-3 次**，深入探索话题
- 只有受访者明确无法或不愿继续时，才可以少于 2 次
- 目的：理解"为什么"、发现有趣的细节、挑战不一致的说法

**追问方向**：
- 为什么？（动机）
- 具体怎么做的？（过程）
- 当时感觉怎么样？（情感）
- 能举个例子吗？（具象化）

**适用场景**：
- 核心探索问题
- 用户体验和决策过程
- 需要深入了解的关键话题

## timed — 限时追问

**设置**：`--follow-up timed --time-budget <分钟>`

**行为**：AI 主持人在 0.1–60 分钟的时间预算内动态追问；`timed` 必须设置 `--time-budget`，其他级别不得设置该参数。

- 默认预算为 2 分钟，CLI 创建时仍应显式传值
- 主持人会尽量使用至少 90% 的预算后再推进；它是探索预算，不是追问次数

**适用场景**：需要控制单题最长探索时间的开放题。

## 追问的通用规则

不管什么级别，追问都必须遵守：

1. **所有追问必须是开放式的**
   - ✅ "为什么选择了这款？"
   - ❌ "是因为价格还是品质？"（二选一）
   - ❌ "是不是因为朋友推荐？"（引导性）

2. **引用受访者的具体内容**（主动倾听）
   - ✅ "你提到了'操作太麻烦'，能具体说说是哪个环节让你觉得麻烦吗？"
   - ❌ "能再多说一点吗？"（太泛）

3. **一次只追问一个方向**，不要同时问两件事

4. **问 why / how / what**，不问 yes/no

## CLI 示例

```bash
# 暖场题：轻度追问
mizzen-cli outline question add <slug> <section-id> \
  --text "你平时喜欢什么休闲活动？" \
  --type open_ended \
  --follow-up light

# 核心题：深度追问
mizzen-cli outline question add <slug> <section-id> \
  --text "你上次退掉一个已购买的产品是什么情况？为什么要退？" \
  --type open_ended \
  --follow-up heavy

# 限时题：最多探索 5 分钟
mizzen-cli outline question add <slug> <section-id> \
  --text "请完整讲述你上次购买这类产品的过程。" \
  --type open_ended \
  --follow-up timed \
  --time-budget 5
```
